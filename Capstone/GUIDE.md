Strategy logic (explained in the Charter, §2 and §9 "Decision log"):
1. The bottleneck is the **power transformer** (50 weeks per lot, one production line): PO on the first
   possible day (end of F08, 16 Apr 2027), **expediting** of both lots, road transport.
2. **Crashing** only on the transformer-driven chains (F23, F24, F29, F31, A08, A10): +EUR 0.9 M of cost,
   Hall A about one month earlier.
3. **Compute lots (EUR 160 M each)** and network lots are paid at order placement, so they are ordered
   **just in time**; for lot 1 air freight (EUR 475 k) costs less than the cost of capital of ordering 35 days earlier.
4. The 2028 DSCR test (Apr–Dec only, with Hall A alone in service) sets the debt capacity: every month of
   Hall A delay removes about 4 pp of debt share and about EUR 9 M of NPV.

## 4. Step by step: open the plan in MS Project and save it as `.mpp`

I cannot create a `.mpp` directly (proprietary binary format). XML is Microsoft Project's official exchange
format and opens without loss.

1. Open **Microsoft Project** (365 / 2019 / 2021, desktop).
2. **File → Open → Browse**, in the file-type drop-down choose **"XML Format (*.xml)"** and select
   `Aurelia_Program_Master_Plan.xml`.
3. In the "Import Wizard" choose **"As a new project"** → Finish.
4. Check the calendar: **Project → Change Working Time** → "Standard" calendar, Mon–Fri 8:00–12:00 /
   13:00–17:00, no holidays. Then **File → Options → Schedule**: Hours per day 8, Hours per week 40,
   Days per month 20, Default task type **Fixed Duration**, "New tasks are effort driven" **off**.
5. Check that all tasks are **Auto Scheduled** (Task Mode column). If some are Manually Scheduled:
   select all → Task → Auto Schedule.
6. Check the dates: **Project → Project Information → Statistics**: Finish must be **19 Apr 2029**;
   milestone "Hall A commercial service" = 9 May 2028 (17:00; commercial service starts the next day,
   10 May), "Hall B commercial service" = 1 Mar 2029, "Final Program Acceptance" = 19 Apr 2029.
   If dates differ by a few days, the cause is almost always the calendar (step 4) or the Task Mode (step 5).
7. Check the resources: **View → Resource Usage** (or Resource Sheet): no resource in red (no
   overallocation). The plan uses **explicit sequencing links** (as in your assignment 1), not automatic
   leveling: **do not run Resource → Level All**.
8. Check the costs: View → Gantt Chart, add the **Cost** column: the project total must be about
   **EUR 583.8 M** (activities 580.8 + expediting 2.3 + transport 0.7; the time-dependent overheads,
   EUR 16.3 M, are only in the financial model because the workbook states they are not resources).
   Columns **Text1** = activity code (F01…O15), **Text2** = project (P1/P2/P3/Procurement), **Text3** = Train/Hall.
9. Read the task **Notes** (icon in the Indicators column): they contain the crashing rules applied, the
   resource-sequencing links, and the expediting and transport costs (entered as Fixed Cost).
10. Optional but recommended: **Project → Set Baseline** to save the baseline, and format the Gantt
    (Format → Critical Tasks) to show the critical path.
11. **File → Save As → type "Project (*.mpp)"** → `Aurelia_Program_Master_Plan.mpp`.
12. Export a PDF/image of the Gantt (File → Print → PDF or Format → Copy Picture) and paste it into the
    Charter, §6.

Free alternative: **ProjectLibre** → File → Open → type "Microsoft Project XML" → same file; save as
`.pod` or File → Save as → XML format.

**If the import fails** (very old Project version): the `Schedule` sheet of the Financial Model lists every
activity with dates, durations, resources and units (including crash units), the `Procurement` sheet the
supply chains, and Annex A of the Charter all the links: with those the plan can be re-entered by hand in 1–2 hours.

## 6. How to regenerate everything (if data or assumptions change)

Requires Python 3 with `openpyxl`, `python-docx`, `mpxj` (+ Java for MPXJ) and LibreOffice for recalculation.
From the `Capstone/model` folder:

```bash
python3 optimize.py            # searches the maximum-NPV solution (~10 minutes) -> solution.json
```

```bash
python3 build_fin_xlsx.py      # Financial Model Excel
```

```bash
python3 export_msp.py          # XML for MS Project
```

```bash
python3 build_docs.py          # Charter, Risk Plan, Risk Register
```

After `build_fin_xlsx.py`, open the file in Excel (or LibreOffice) and save it to recalculate the formulas
(already done for the delivered version). To change a precedence rule: `engine.py`, list `LINKS`
(and `NEEDS` for deliveries). To change a decision manually (e.g. not expediting a lot): edit
`solution.json` and rerun the last three scripts.

## 7. Structure of the Financial Model (to explain it to the instructor)

- `Inputs`: case data (blue), team levers (yellow: discounting convention, delay months for sensitivity).
- `Schedule`: all activities with dates and costs (identical to MS Project).
- `Procurement`: POs, lead-time rule, expediting, transport, delivery vs required-on-site date (float).
- `ActivityCost_M`: each activity's cost spread over months with `NETWORKDAYS` (prorated accrual).
- `Monthly`: CAPEX, overheads, revenue, electricity, **unlevered FCFF**, cumulative, discount factors, PV.
- `Financing`: D/E table 0–100 % in 0.5 % steps, WACC, NPV, DSCR per year, feasibility, **automatic selection
  of the highest feasible debt share**; covenant sensitivities 1.50x / 1.80x.
- `Debt_Ledger`: monthly ledger of draws/interest/principal, annual post-grace DSCR test.
- `Resources`: peak usage vs Max Units check.
- `Sensitivity`: NPV vs selling rate, electricity price, WACC.
- `Summary`: every output required by the briefing.
